# 旅行档案备份与恢复

本项目是一份轻量旅行档案。备份与恢复是一条完整流程：**当前站点生成 ZIP → 下载并私下保存 → 空白新实例上传 → 校验和预览 → 管理员确认 → 手动重启 → 检查结果**。

通用 Docker 镜像只包含代码、地图和占位图；不会内置旅行记录、账号或私人照片。

## 从当前站点导出

1. 管理员登录后打开 **管理后台 → 备份恢复**（`/admin/restore`）。
2. 点击 **生成并下载备份 ZIP**。
3. 确认浏览器已完成下载，把文件保存到站点之外的私人位置。

包内结构：

```text
travel.db                 # SQLite 一致性快照
uploads/                  # 数据库登记的上传图片
legacy-images/images/     # 现有的历史图片（若有）
backup.json               # 格式版本、生成时间、文件大小和 SHA-256
```

导出包括已归档记录、目的地、足迹、时间轴、旅行计划、攻略入口、费用、日记、照片，以及账号、设置和审计数据。

### 一致性和容量

- 不直接复制运行中的 SQLite 文件。导出期间取得短暂的数据库写锁，使用 `VACUUM INTO` 创建一致性快照，在同一写锁保护下复制媒体文件；ZIP 压缩和下载不占用写锁。
- 复制时编辑请求可能短暂等待；请避免同时大量上传或修改。仅生成一份备份，不会改动业务内容。
- 所有受管图片必须存在且名称合法；缺图或磁盘空间不足时明确失败，不生成悄悄缺图的备份。
- 图片只读取配置的上传和历史目录，不包含 `.env`、服务器凭据、日志、恢复暂存文件或源码。
- ZIP 最大 **48 MiB**，解压后最大 **350 MiB**，最多 **800 个条目**；单个数据库最大 100 MiB，单张媒体文件最大 18 MiB。导出端与恢复端使用相同限制。
- 正常下载结束后删除导出临时文件；进程意外退出的临时目录在后续导出时回收超过 24 小时的项目。

**ZIP 未加密，包含账号哈希和私密照片。** 不要把备份发给 AI、公开文件分享网站或提交到 Git。建议保留多份异地副本，重要编辑前和镜像升级前各备份一次，并定期在临时空白实例做恢复演练。

## 网页恢复到新实例

1. 在 StackNest 创建本应用的空白实例，容器端口 `3000`，持久化目录目标 `/app/data`，配置首次管理员。
2. 登录新实例，打开 `/admin/restore`，选择自己可信来源的 ZIP。
3. 网页采用 **512 KiB 分块**上传，校验每块和整包 SHA-256。中断或刷新后，重新选择同一个文件即可续传；分块保留 2 小时。
4. 系统校验 ZIP 路径、文件数量、解压大小、SQLite 完整性与外键。新格式还必须逐文件匹配 `backup.json` 的 SHA-256，不允许缺文件、多文件或内容篡改。
5. 支持的旧版本数据库只在**隔离副本**执行本仓库的迁移，再生成预览；未知新版本、无迁移历史或非本项目数据库会拒绝。此时当前站点尚未改变。
6. 核对足迹、目的地、时间轴、计划、日记、费用和媒体数量，勾选确认并点击 **确认恢复，重启后生效**。
7. 在 StackNest 手动重启应用。启动脚本准备图片和新数据库，保留恢复前数据库副本，再切换到恢复后的数据库。
8. 用新站点管理员重新登录，在 `/admin/restore` 查看结果并抽查照片、费用和日记；需要第二位成员时重新创建编辑账号。

### 安全边界

- 只允许同源管理员发起导出和恢复；编辑者或 CLI Token 不能下载整站备份。
- 网页整站恢复只允许**完全空白的新实例**，包括没有归档记录、独立日记、媒体和旅行计划。已有内容时拒绝覆盖；不要为了绕过校验手动清空真实数据。
- 保留当前新实例管理员的用户名、显示名和密码。备份中的旧用户停用，旧会话、API Token、导入草稿和登录限流记录清空。
- 停用的历史用户仅用于保留照片归属和审计，不占用两位启用成员名额；历史登录名仍保留，新成员可使用不同用户名。
- 站点名称、币种和公开/私密模式会随备份恢复。确认前请核对备份来源和访问范围；恢复后需要保密时检查站点设置。
- 归档状态保留。已归档地点的相关时间轴、日记和照片仍只在编辑室保留。
- 拒绝符号链接、越界路径、自定义数据库触发器/视图和不兼容数据库，不运行备份内的脚本。
- 媒体复制有任务所有权清单：先写同目录的任务临时文件、校验并刷盘，再以不覆盖已有目标的原子硬链接发布；中断产生的半文件只在临时路径，下次可以安全重做。常见 ext4/NTFS 支持此操作；文件系统不支持时拒绝恢复，不降级为覆盖写入。冲突拒绝覆盖，被人工改变的文件会保留所有权记录供检查。数据库切换失败会撤回本任务图片，原数据库仍保留。重命名中断时，下次启动优先恢复原数据库并记录失败。
- 若数据库已经切换、仅完成状态写入中断，保留任务标记，下次重启补全状态，不重复覆盖数据。

恢复前原数据库保存在该任务的 `restore-staging/<id>/previous-db.db`。这是运维回退材料，不是对外下载入口；不要删除唯一可用副本。恢复成功后、确认业务数据正确并另存独立备份，再按自身保留策略处理持久化卷中的旧任务。

## 旧模型升级

轻量版不再使用 `TravelPlanDay`、手工 `actualBudget`、付款人或收据字段。实际支出统一从四类费用计算。

升级迁移不会悄悄丢弃这些字段中已有的值：存在历史值时，先保存到 `AppSetting` 的 `legacy_lightweight_20261106` JSON 运维存档，再移除未使用的模型和字段。该只读存档随数据库备份保留，不重新提供半成品 UI。旧备份恢复时同样经过此迁移。

## 超出网页容量：停机备份与恢复

超过网页 ZIP 容量时，先停止容器，再把一致的数据库和图片目录复制到仓库之外：

```text
/app/data/travel.db
/app/data/uploads/
/app/data/legacy-images/
```

若配置了自定义 `UPLOAD_DIR` 或 `LEGACY_MEDIA_DIR`，同时保存对应目录。不要在容器仍运行时只复制 SQLite 主文件，也不要把单独的 `-wal`、`-shm` 文件当成完整数据库。

手动恢复前备份目标实例，确认备份账号、密码哈希和 Token 的安全性，再在**停机状态**恢复全部文件；确保容器用户 UID `1001` 可读写。手动复制不会执行网页恢复的“保留新管理员、停用旧凭据”流程，必须由运维人员处理账号授权后再对外开放。启动时 Prisma 会应用当前版本迁移。

## 验证

`npm run test:backup:restore` 使用合成数据和隔离目录，覆盖真实导出往返、文件校验、篡改拒绝、旧库升级与历史值保留、归档状态、费用/日记/照片恢复、账号隔离、上传续传、媒体复制重放和数据库切换中断回退，不会操作真实 `data/travel.db`。
